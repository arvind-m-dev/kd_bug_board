
## BugFlow architecture
- Use shared frontend confirmation and error feedback for sign-out and portal access changes; keep failed confirmations open and offer retry for failed reads so actions remain recoverable without altering server authorization.
- Workspace routes use a shared server-session beforeLoad check and redirect to the standalone login page before rendering; member token routes keep their own scoped access validation.
- Admin cookies are Secure, HttpOnly and partitioned with SameSite=None for embedded preview support; mutations retain same-origin validation and sign-in verifies session readback before navigating.
- Preserve TanStack Start file-based routes and shadcn controls; all content routes carry their own metadata for reliable navigation and previews.
- Keep pure domain rules in `src/lib/bugflow.ts` and `src/lib/bug-workflow.ts`, presentation in `src/components/bugflow`, and server-only integrations behind server functions; this separates permission/count rules from UI.
- Unconfigured views display unavailable data, never fabricated records or success; live features require approved development connections.
- Keep proposed Neon schema changes in versioned SQL files under `database/` and apply them to the Neon database referenced by DATABASE_URL; this makes database changes reviewable and keeps credentials out of app code.
- AI onboarding uses a server-only call to an OpenAI-compatible API (AI_API_KEY) and verifies a live Neon Admin session before spending credits; only an authorized atomic member save grants selected role-limited permissions and actual project scope, never generated guidance.
- Admin sign-in verifies configured email and password only on the server and maps the verified owner to expiring hashed sessions in Neon; member links use hash-only validation plus server-encrypted recovery for Admin copying, and are validated for role, active user, expiry and revocation on every read.

- Bug reports and changes use shared scoped server functions for Admin and member panels, validate active access and explicit permissions, and atomically write immutable actor history; optimistic versions and request IDs protect retries and concurrent edits.

- Member lifecycle uses soft deletion and atomic audit records, retaining bug references while revoking all member portals; welcome acknowledgements live on the validated portal so first-visit behavior persists across devices.
- A shared theme provider updates semantic CSS variables and saves only the theme preference in browser storage; all workspace and member pages use the same theme controls.
- Single-project forms retain scoped IDs while hiding redundant selectors; compact tables omit project columns without changing server authorization.

- Shared report validation derives omitted titles and actual results from the submitted description; contextual facts remain empty to avoid invented data.
- Expanded bug rows reuse the shared report presentation and scoped detail query; inline assignment uses the existing authorized audited mutation.
- Settings uses the shared scoped workspace query for option and assignee management; member creation invalidates member, workspace and detail queries so eligible assignment choices refresh immediately.

- An MCP server at `/api/mcp` lets any AI client read and report bugs using a Bearer AI token scoped to one panel (Admin or a member); tokens are hashed in `bugflow.ai_tokens`, resolved by the `'ai'` access kind through the same scoped server functions as the app, and `checkOrigin` no-ops outside the Start request runtime because MCP calls carry no cookie. No delete tool is exposed. claude.ai/ChatGPT connect over OAuth 2.1 + PKCE (`/api/oauth/*` and `/.well-known/oauth-*` in `src/server.ts` → `oauth-routes.server.ts`); the consent sign-in reuses the Admin unlock or a member portal link, auth codes are single-use and hashed (migration `017`), and the issued access token is a `bugflow.ai_tokens` row so OAuth connections are revocable in Settings → AI access. MCP tools answer in compact text, not JSON, to keep AI reading cheap.
- Timed video marks live on `bugflow.bug_media.marks` (migration `018`) as frame-relative shapes with start/end seconds and an optimistic `marks_version`; `saveVideoMarks` checks upload permission and writes the audit row in the same statement. The recording is never re-encoded; `VideoPlayer` (`video-marks.tsx`) draws marks over playback for every viewer.
- Uploads run in a tab-wide queue (`media-queue.ts`) so reports can be submitted while recordings compress; background files show in the uploads tray. MP4/MOV files get a browser-side faststart (`mp4-faststart.ts`) and signed view links are stable per 5-minute window so the browser cache is reused.
- Removing a single file moves it to the Trash for 30 days (`bug_media.restorable_until`, migration `019`): the media sweep purges only rows whose window is null or past; restore/delete-forever are available to the uploader or Admin from My media and the Admin Trash.
- Media viewing is view-only for everyone. Mark-up is only for the uploader: on the local file in the upload queue, or on their own files from My media in the member portal (`upload-markup.tsx`; images get a marked-up copy): images are replaced by the marked-up version, recordings carry timed marks saved right after attach (`saveVideoMarks` accepts only the uploader). Bug panels stage files until "Upload" for that reason.
- Each image/recording uploads a small JPEG preview to `<key>.thumb.jpg` (`has_thumb`, migration `020`); lists show previews and never load video data. Recordings over ~5 Mbps are re-encoded (MP4 preferred) before upload so they stream quickly.
- The notification bell skips file events (`bug.media_*`, `QUIET_ACTION_PREFIXES` in `notifications.ts`); they stay in the activity log and on each bug.
- Signed-out `/admin*` visits redirect to `/login?redirect=<path>` (same-site paths only, `safeReturnPath`); an Admin session that ends mid-use (`isAdminSessionError`) clears caches and returns to sign-in. Admin password checks (sign-in and OAuth consent) are throttled per client address.
- Links meant for other people use `shareOrigin()` (`VITE_SITE_URL` when copied on localhost) and warn when still local. Uploads go browser → bucket, so the bucket CORS rule must list every app address; Settings → Media storage → Test runs the browser's preflight per address (`corsBlockedOrigins`).
- Bug report edits are version-checked in one statement that also writes the audit row; detail/step writes depend on that row. Non-Admin edits cannot change priority or severity.
- Phase 2.1 due dates (migration 021): `bugs.due_on` is an optional plain date. "Overdue" is derived, never stored — a bug is overdue when `due_on` is before today (in the workspace time zone, settings key `workspace.timeZone`, default UTC) and the status is not closed (`CLOSED_STATUSES` in `src/lib/bugflow.ts`). Only `plan` holders (Admin always; QA preset) may set or clear a date (`maySetDue`); the value is dropped on report and ignored on edit for anyone else. The change is audited inside the existing `bug.edited` action. Overview overdue count comes from SQL; the list filter is client-side over the loaded page, matching the other filters.
